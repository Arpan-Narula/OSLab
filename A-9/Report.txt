Q1 — Printing the page table.
I added a new syscall vmprint() that walks the two-level page directory of the calling process. For each present PDE below KERNBASE, I find the page table it points to, and for each present PTE in it I print the virtual address, the physical frame address, and the P/W/U flags. I skip anything at or above KERNBASE since that’s kernel space, not the process’s own mappings. At the end I print the total number of valid user pages and how many page-table pages were used. pttest.c calls vmprint() once at start, then calls sbrk(4*4096) and calls vmprint() again — the second output shows exactly 4 new va/pa lines compared to the first, confirming sbrk mapped exactly 4 new pages.

Q2 — Lazy allocation / page fault handling.
Normally sbrk() calls allocuvm() right away, which actually allocates and maps physical pages. I changed sys_sbrk() so that when n > 0 it only bumps myproc()->sz — no page is mapped yet. The real allocation now happens lazily, inside the page fault handler in trap.c: when T_PGFLT fires, I read the faulting address with rcr2(). If it’s within the process’s allocated size (< sz), I kalloc() a page, zero it, and map it in with PTE_W | PTE_U, then increment a new nfaults counter in struct proc and let the process resume. If the address is outside sz, I print the pid/address and kill the process. Since pages can now legitimately be “promised” but not yet mapped, I also had to fix copyuvm() (used by fork) so it skips copying pages that were never actually allocated instead of panicking; deallocuvm() turned out to already tolerate this case since it checks PTE_P before freeing. faulttest.c grows the heap by 32 pages, touches exactly 5 of them, and prints getfaults(), which correctly shows 5. It then forks and has the child touch an address past the allocated size — the child gets killed by the trap handler while the parent keeps running and prints a message, showing the fault only affects the one process.

Q3 — FIFO vs LRU page replacement.
pagerepl.c is a user-space simulator (no kernel changes needed) that takes the number of frames and a reference string as command-line arguments. For every reference it checks whether the page is already in a frame (hit) or not (fault); on a fault, FIFO evicts the oldest-loaded page using a circular pointer, while LRU evicts whichever frame has the oldest “last used” timestamp. For each reference I print the current frame contents and whether it was a HIT or FAULT. With the given 20-reference string and 3 frames, FIFO produces 15 faults and LRU produces 12 faults, matching the expected results. I then ran both algorithms again for 3, 4, and 5 frames and printed a summary table of faults and hit ratio for each, which shows both algorithms improving (fewer faults, higher hit ratio) as the number of frames increases, with LRU consistently doing at least as well as FIFO.
